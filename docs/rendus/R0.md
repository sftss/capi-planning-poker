# R0 : cas d'utilisation et user stories

Binôme **B2-11**. Séance 0, date : 16/10/2026.

## 1. CU-01 : Estimer le backlog d'un projet

| Rubrique | Contenu |
|---|---|
| **Portée et niveau** | application CAPI · utilisateur |
| **Acteur principal** | Scrum Master (Organisateur de la partie) |
| **Intervenants et intérêts** | **Product Owner** : il veut avoir les user stories du backlog estimées <br> **Joueur** (développeur, testeur) : il veut estimer la difficulté des tâches à effectuer, sans être influencé par les autres joueurs |
| **Déclencheur** | Le Scrum Master souhaite évaluer des user stories |
| **Garanties** | **Minimales** : Le fichier de backlog reste intact. En cas d'interruption (carte café), l'état d'avancement de la partie est sauvegardé <br> **De succès** : Tout le backlog est estimé et l'application enregistre un fichier JSON avec la difficulté estimée pour chaque fonctionnalité |

### Scénario nominal

1. Le Scrum Master configure la partie (nombre de joueurs, pseudos et règle de validation).
2. Le Scrum Master charge le fichier JSON contenant le backlog.
3. L'application présente la première fonctionnalité non estimée du backlog.
4. Les joueurs votent sur la fonctionnalité sans voir les cartes des autres.
5. L'application valide l'estimation selon la règle choisie.
6. L'application enregistre l'estimation validée.
7. L'application exporte les résultats dans un fichier JSON contenant les difficultés estimées.

### Extensions

- **1a.** La configuration est invalide (moins de 2 joueurs, pseudo vide ou déjà pris) :
  - 1a1. L'application affiche un message d'erreur indiquant la valeur refusée.
  - 1a2. Le scénario repart à l'étape 1.
- **2a.** Le fichier chargé (backlog ou sauvegarde) est invalide :
  - 2a1. L'application affiche un message d'erreur indiquant que le fichier ne peut pas être lu.
  - 2a2. Le scénario repart à l'étape 2 pour charger un fichier valide. Si le Scrum Master abandonne, fin du CU en échec : aucune partie n'est créée.
- **2b.** L'utilisateur reprend une partie sauvegardée :
  - 2b1. Le Scrum Master choisit de charger un fichier JSON de sauvegarde au lieu d'un nouveau backlog.
  - 2b2. L'application restaure la configuration de la partie et l'état d'avancement.
  - 2b3. Le scénario reprend directement à l'étape 3.
- **4a.** Tous les joueurs jouent la carte café :
  - 4a1. L'application sauvegarde automatiquement l'état d'avancement de la partie dans un fichier JSON.
  - 4a2. Fin du CU en échec : la partie est suspendue et pourra être reprise (extension 2b).
- **6a.** Il reste des fonctionnalités non estimées :
  - 6a1. Le scénario repart à l'étape 3 pour traiter la fonctionnalité suivante.

## 2. Les 6 user stories

| US | Texte (En tant que... je veux... afin de...) | Source | MoSCoW |
|---|---|---|---|
| US-01 | En tant que Scrum Master, je veux configurer les joueurs et charger le fichier JSON afin d'initialiser la partie avec le backlog à estimer. | CU-01 étapes 1 et 2, extensions 1a et 2a | Must |
| US-02 | En tant que joueur, je veux que la règle de validation stricte (unanimité) soit appliquée afin de m'assurer d'un accord général sur l'estimation. | CU-01 étapes 1 et 5 | Must |
| US-03 | En tant que Scrum Master, je veux que, à partir du deuxième tour, la fonctionnalité soit validée à la médiane des cartes, afin de conclure sans exiger l'unanimité une fois la discussion faite. | CU-01 étapes 1 et 5 | Must |
| US-04 | En tant que joueur, je veux que le premier tour de vote requière toujours l'unanimité (quelle que soit la règle choisie) afin de forcer un temps de discussion initial en cas de désaccord. | CU-01 étape 5 | Must |
| US-05 | En tant que Scrum Master, je veux exporter un fichier JSON contenant les difficultés estimées afin de transmettre les estimations au Product Owner. | CU-01 étape 7 | Must |
| US-06 | En tant que joueur, je veux choisir une carte sans voir celles des autres, puis que toutes les cartes soient révélées ensemble, afin de donner mon estimation sans être influencé. | CU-01 étape 4 | Must |

Parmi ces 6 US, 3 portent les règles de validation : règle stricte, règle choisie, premier tour à l'unanimité.
